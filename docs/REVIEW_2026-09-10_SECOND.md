## 확정된 보강
- 두 MCP는 부칙 보강 후보의 법령명을 검색 결과와 회수 XML에서 확인한다. 다른 법령은 병합하지 않으며 NTS는 요청 제명과 본문이 불일치하면 오류를 반환한다.
- OLTA 긴 citation 절단은 숫자(digits) 경계를 보존하며, 과거 후보가 0건이면 현행 시점으로만 fallback하고 현행 시점 경고를 남긴다.
- 구조 연결 복원은 법적 승인과 다르며 원문·제외조건·검토 상태를 자동 승인하지 않는다.

## 이식한 3개 규칙
1. 개행된 조문은 줄 시작을 조 경계로 보존하고, 줄바꿈 없는 원문에서만 느슨한 fallback을 허용한다.
2. 시행일 파싱 실패 때 공포일을 대체하지 않고 `unknown`으로 남기며, 연계 판정은 보류한다.
3. 동일 문구는 중간 무개정이나 부칙 무관을 뜻하지 않으므로 출력 설명을 완화하고 법적 판정을 만들지 않는다.
- 플랫폼의 scope/ALIVE·좌표 엔진은 과거 판본·조항호목 계보·검토 상태 DB를 전제로 하므로 on-demand MCP에 그대로 이식하면 오귀속될 수 있다. 단순 유사도는 법적 유효성이 아니다.

## 적용 보류
- ALIVE 0.5 유사도를 법적 판정으로 사용하지 않는다.
- 조항호목 제외 처리·각 호 범위 전체 엔진, 상대 기간 계산·조별 시행일 자동 해소는 보류한다.
- 원문 증거가 확보된 결정적 guard만 적용하며 actual DB 전수 적용 승인으로 해석하지 않는다.

## 잔여 한계와 보안
- NTS response body cap은 없고, OLTA fetch 30초 상한은 전체 tool budget이 아니다. 한 줄 부칙 괄호 fallback도 모호성이 남는다.
- 추가 lookup을 줄이거나 오매칭 후보를 배제해 토큰·시간을 절약할 수 있으나 수치 benchmark는 측정하지 않았다.
- 보안 audit은 양쪽 최종 결과 0건이며 완전한 보안 감사 완료를 뜻하지 않는다.
- 기존 앱의 active 연결은 갱신하지 않았고 독립 SDK 검증과 구별한다. 과거판본·적용시기·법률 의미의 전수 확정도 아니다.
