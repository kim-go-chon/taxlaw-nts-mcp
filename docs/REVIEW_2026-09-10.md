# 2026-09-10 MCP 4관점 리뷰 결과

## 범위와 기준

- 대상: `taxlaw-nts-mcp` 0.27.8, `taxlaw-olta-mcp` 0.1.1. `korean-law` 자체 코드는 변경하지 않았다.
- 모델 배정: Astra `low`는 설계·디버깅·검증, Luna `max`는 단순 문서 작업에 사용했다.
- 저장소: NTS는 기존 public 저장소, OLTA는 [private 저장소](https://github.com/kim-go-chon/taxlaw-olta-mcp)를 새로 만들었다.

## 4관점 리뷰 결과

| 관점 | 리뷰 결과 | 판정 |
|---|---|---|
| 효과성 | `title/includes` 오탐을 제거하고 번호 필드의 전체 ID와 숫자 경계만 인용 실존 근거로 사용한다. 본문 파싱 fail-open을 제거하고 실패 캐시를 삭제한다. encoded `<별표>`를 보존하고 임의 ID 숫자 추출을 제한한다. `korean-law` ID와 OLTA `num`의 차이를 안내한다. | 수정·검증 완료 |
| 토큰 효율성 | 고정 5단의 빈 섹션과 질문 강제를 제거하면서 출처는 보존한다. `full`이 50,000자를 넘으면 원문 링크를 안내한다. 현재 확인되지 않은 `korean-law` 고장을 단정하던 표현을 제거하고 동일 원문을 재사용한다. | 수정·검증 완료 |
| 작업시간 | 최초 연결 실패 재시도는 4회에서 1회로 줄었고 mock 시간은 4,935ms에서 1ms가 됐다. OLTA 본문 소비 포함 timeout은 15초, fetch 총 상한은 30초다. 이 mock 수치는 실제 네트워크 성능 향상으로 해석하지 않는다. | 수정·검증 완료 |
| 보안 | OLTA는 동일 출처 redirect 5회, 외부 redirect 차단, 16MB 상한을 적용한다. 429/503/504 재시도 budget 소진 시 `undefined` 대신 HTTP 상태를 기록한다. NTS·OLTA 교차검증은 PASS다. 양쪽 `qs`를 6.15.3에서 6.16.0으로 표적 업데이트했고 `npm audit --omit=dev --json` 취약점은 0건이다. `src`·`test`·`scripts`·`docs` secret pattern scan은 미발견이다(완전 감사는 아님). | 통과 |

## 잔여 한계

- NTS response body에는 별도 메모리 상한이 없다.
- OLTA 30초 상한은 개별 fetch 기준이며 복합 도구 전체 budget을 보장하지 않는다.
- 새 stdio 프로세스 검증은 이미 실행 중인 호스트 MCP에 대한 재연결까지 보장하지 않는다.
- secret scan은 지정 경로의 패턴 점검 결과이며 완전한 보안 감사가 아니다.
- 토큰 사용량은 실제 tokenizer로 측정하지 않았으며, 문자 수는 대리지표다.
- 원문 요약의 법적 정확성을 전수 보증하지 않는다.
